Photo Drop: three directions for the launcher UI

The app is a remote control for a Python server running inside Termux on the owner's Samsung. Four real actions: start it, get the link, send it to one person, know there is room on the phone. Usually five seconds, one-handed. Every decision below is judged against that.

A Live Header

Status strip owns the top of the screen and takes a distinct colour per state, so "is it on?" resolves before a word is read. One control that changes identity with state, replacing the Start/Stop pair where one is always disabled. Everything below is one scroll of progressively less important detail. Smallest diff, best legibility in sun.

C Tap to Toggle

The server is the interface. A large orb is the switch, the whole screen goes green when live, and the link slides up from a bottom sheet only once there is something to show. The state change is felt rather than read. Most work of the three: it needs a real sheet transition and a hold-to-stop guard, which is not optional, so a pocket tap cannot kill an upload mid flight.

Recommendation: A. It fixes the twelve defects in the plan for roughly the diff size of the current app, it is the only one that survives being read in a bright room, and it does not put Stop behind an overflow or an undiscoverable long press. Borrow from B: permanent QR, which is worth more than the rest of B because it matches how the app is really used. Borrow from C: one live indicator so the 7 second poll has a visible heartbeat. Nothing else from C.

Open questions

  1. A only, or spec B and C too? The plan specs A in full detail. Mocks show all three.
  2. Keep the green, or move toward T3 Code's palette? The plan warms the neutrals to capture the T3 character without abandoning the brand. The literal brand palette is #db2777 primary with #501854 foreground, and swapping costs nothing.
  3. Bundle DM Sans? Three static weights, what T3 Code uses. Currently the system font.
  4. Per session upload detail? /healthz only returns a count of sessions. Names, file counts and sizes live only on the owner page. A richer feed needs a new authenticated endpoint in server.py. Separate task, or is "3 upload sessions today" enough?
